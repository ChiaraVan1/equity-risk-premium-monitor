# ERP 工作台数据核验 SOP（v0.3 · 定稿）

> 目的：把"数据对不对、逻辑对不对"变成每次都能复现的判断，而不是靠人看一眼。
> 范围：`erp_mon` 仓库全链路（触发 → 取数 → 计算 → 派生 → 呈现 → 提醒）+ 工作台对外展示。
> 状态：v0.3 定稿。六条决定 + 首期规则 + 核验时点均已确认。

## 一、判定等级与总规则

| 等级 | 含义 | 处理 |
|---|---|---|
| **PASS** | 与判据相符 | 记录留痕 |
| **WARN** | 可疑但可用（陈旧、样本少、口径近似） | 记录，**汇总进同一条告警** |
| **FAIL** | 明显错误或链路中断 | 整期不通过，立即告警 |
| **SKIP** | 无独立源或环境不具备 | **必须写明"本期未验"及原因**，不得当 PASS |

**总规则**
1. 任一 FAIL → 整期"不通过"，当天告警。
2. 有 WARN（无论几条）→ 也告警，但**只发一条**，里面逐条列出。
3. 全 PASS → 只落盘，不推送。
4. SKIP 不计入通过率，报告顶部单列"本期未验项"。
5. 核验**只读**：不修数据、不重跑取数、不改 config。

## 二、六层检查清单

### L0 运行层（链路是否真的跑了）

| 检查项 | 依据 | 判据 | 等级 |
|---|---|---|---|
| 当日任务成功 | GitHub run `conclusion` | 当日 18:30 批次 `success` | FAIL |
| 校验器自身在跑 | `data/freshness_report.json` 生成时间 | ≤26h；26–48h → WARN；>48h 或缺失 → FAIL | WARN/FAIL |
| ERP 完成时点 | 当日 run 的 commit 时间 | ≤18:50（下游 19:00 要读） | WARN |
| 报告产物日期 | `docs/report.html` | = 数据日；落后 1 交易日 → WARN，≥2 → FAIL | WARN/FAIL |

### L1 取数层（陈旧、静默断链、量纲）

| # | 检查项 | 依据 | 判据 | 等级 |
|---|---|---|---|---|
| 1 | A 股指数/ETF 新鲜度 | `data/erp_*.csv`、`etf_price.csv` 末行日期 | 落后数据日 ≤1 交易日；2 日 → WARN；≥3 日 → FAIL | WARN/FAIL |
| 2 | 海外/FRED 新鲜度 | `erp_SPY/QQQ/EWQ/EWG/EWJ/EEM.csv`、`tips_10y.csv` | 落后 ≤1 自然日；≥2 日 → FAIL | FAIL |
| 3 | 关键列非空 | 每只末 3 行 `PE`/`ERP`/`Bond_Yield_10Y` | 任一空 → WARN；3 行全空 → FAIL | WARN/FAIL |
| 4 | **量纲** | `erp_*.csv` 的 `Bond_Yield_10Y`、`ERP` | `Bond_Yield_10Y` 落在 0–0.2（**小数**口径）；`ERP` 落在 −0.1–0.2（小数）；越界 → FAIL | FAIL |
| 5 | **量纲** | `tips_10y.csv` 的 `real_yield`/`nominal_10y`/`inflation_expectation` | 落在 −2–8（**百分数**口径）；越界 → FAIL | FAIL |
| 6 | 个股收盘价 | `erp_600585/601006/600600.csv` 的 `IndexClose` | 末行必须非空 | FAIL |
| 7 | 指数收盘价 | `erp_<指数>.csv` 的 `IndexClose` | 为空仅 WARN（价格主用 `etf_price.csv`） | WARN |
| 8 | 数值卡住 | `data/_pe_value_streak.json` | `stale_flag=true` → WARN | WARN |
| 9 | 文件覆盖 | `config.json` 138 个标的 | 每只有对应文件或标 price-only；缺一 → FAIL | FAIL |

> **为什么单列量纲**：`erp_*.csv` 的国债存小数（`0.0161`=1.61%），`tips_10y.csv` 存百分数（`2.86`）。若哪天按小数口径写入 TIPS 值，ERP 会瞬间变 −2.84，分位全乱而报表照出。这是必须挡住的错。

### L2 计算层（数字算得对不对）

| 检查项 | 依据 | 判据 | 等级 |
|---|---|---|---|
| ERP 恒等式 | 每只末个有效行 | `ERP = 1/PE − Bond_Yield_10Y`，误差 ≤2bp；≤10bp → WARN；>10bp → FAIL | WARN/FAIL |
| 涨跌幅交叉一致 | `index_pct.csv` vs `etf_price.csv` 同日变动 | 差值 ≤1.0pct；>2pct → FAIL（两条独立抓取路径互校） | WARN/FAIL |
| 分位口径（930794） | `erp_930794.csv` | 样本 ≥3000 条且起始 ≤2006-01-01（全历史真实样本） | WARN |

### L3 派生层（档位、上限、买点、单位）

| 检查项 | 依据 | 判据 | 等级 |
|---|---|---|---|
| 回本价复算 | `dividend_payback_candidates.csv` | `回本价13年 = 作者预测未来13年(亿) ÷ 最新股本(亿股)`，误差 ≤0.02 元 | FAIL |
| **单位换算一致** | 同上，`备注` 与数值列 | 备注写"作者单位万亿"的行，数值列必须是换算后的**亿**（1.9 万亿 → 19000）；列头单位与数值一致；出现未换算的原始值 → FAIL | FAIL |
| 网格档位 | `data/grid_state.csv`（云端由 secret 还原） | anchor 数=13、无重复、与上期一致（变 → WARN 并列差异）；缺失 → SKIP | WARN |
| 单档定额 | config `source` 分流 | 指数/ETF 3000、个股 5000 | FAIL |
| 6% 上限分母 | `data/portfolio_total.csv` | `TOTAL` 存在且基准日 ≤45 天；超期 → WARN；缺失 → SKIP | WARN |

### L4 呈现层（工作台显示的等于数据文件的）

| 检查项 | 依据 | 判据 | 等级 |
|---|---|---|---|
| 取数一致 | `docs/report.html`、日报 | 总资产 = `portfolio_total.csv` 的 `TOTAL`；标的数 = config 实际数 | FAIL |
| 缺数显式化 | 各区块 | 取不到必须显示"未取到/待更新"，不得留空或静默用旧值 | FAIL |
| 产物完整性 | `docs/report.html` | >20KB 且含档位、ERP、候选池三个区块标题 | FAIL |

### L5 提醒层（该发的发、不该发的不发）

> 推送送达**不检查**（Server酱无回执）。

| 检查项 | 依据 | 判据 | 等级 |
|---|---|---|---|
| 目标价范围 | `fund-daily-report` config `_policy` | 只推榜内、`armed=true`；归档 7 只零出现 | FAIL |
| **每日一次** | `local_alerts.json` | **每交易日最多提醒 1 次**；同一交易日内重复推送 → FAIL；跨交易日未推（条件仍成立）→ FAIL | FAIL |
| MA20 提示 | `ma20_check.py` 输出 | 只在状态翻转日出现 | WARN |
| 下游可读 | `etf_price_adj.csv` commit 时间 | 19:00 前已更新（基金日报 MA20 依赖它） | WARN |

## 三、抽查机制（针对"取到的数据本身是不是错的"）

自动化只能证明内部自洽，证明不了外部属实，因此每期必做。

**抽样规则**
- 每期固定 6 只：3 只个股（600585/601006/600600）全查 + 3 只 ETF/指数按"期号 mod 池大小"轮换。
- 一年内所有标的至少被抽查 1 次。

**独立源与容差**

| 对象 | 独立源 | 容差 |
|---|---|---|
| 个股收盘价 | 东方财富 / 腾讯（两源互校） | ≤0.6% |
| 个股 PE | 东方财富 `f9` | ≤2%（**超差记 WARN，不记 FAIL**） |
| ETF 价格（如 518880） | 东方财富 | ≤0.6% |
| 指数涨跌幅 | `index_pct.csv` ↔ `etf_price.csv` 反推 | ≤1.0pct |
| 国债收益率 | FRED（美债）/ 中债（CN10Y） | ≤5bp |

**无法独立验证（必须写进报告）**
- A 股指数 PE：无公开可比独立源 → SKIP，季度人工到中证指数官网抽查 2 只。
- 海外 PE（EWQ/EWG/EWJ/EEM）：STATUS 已标估算值 → SKIP。
- 股息率：需逐只查公告 → SKIP，随季度复盘人工抽查。

## 四、频率、时间线与触发

| 项 | 时间 | 说明 |
|---|---|---|
| ERP 主报告 | 18:30 触发，18:45 左右发出 | 实测常在此完成 |
| 基金日报 | **19:00**（原 17:30） | 接在 ERP 之后，MA20 拿到当日 `etf_price_adj.csv` |
| 本 SOP 核验 | **每月 1 日、16 日 19:15** | 半月一次；ERP 与基金日报两套都跑完后才执行（不是并行） |
| 手动 | 任意 | `workflow_dispatch`，可指定 `sample` / `dry_run` |
| 例外 | 改 config / 换数据源 / 升级 akshare 后 | 手动补跑全量 |

> 19:00 的前提：ERP 在 18:50 前 push 完。若某天 ERP 拖到 19:00 后，基金日报会读到前一天文件——由 L5"下游可读"这条 WARN 抓出。

## 五、产物与告警

**产物**（路径固定）
1. `docs/VERIFY_REPORT.md` —— 核对表（每期覆盖）
2. `data/verify_report.json` —— 机器可读，供趋势对比
3. 微信告警（FAIL 或 WARN 时发**一条**）

**核对表格式**

| 层 | 检查项 | 期望 | 实际 | 结论 | 证据 |
|---|---|---|---|---|---|

证据写"文件:行号/字段"，如 `data/erp_000300.csv:末行 IndexClose 空`。

**告警文案（一条搞定，固定四段）**
1. 结论：不通过 / 通过但有警告（FAIL n / WARN m / SKIP k）
2. FAIL 逐条
3. WARN 逐条（合并在此，不单独发）
4. 未验证项（没有写"无"）

---

## 六、明确不做的事

- 不自动修数据、不自动重跑取数、不自动改 config / 阈值。
- 取不到不跳过，记 SKIP 并写明。
- 不因 `ok=true` 认定没问题。
- 不把"上次也是这个值"当正常。

**备注列的用途（为什么留着）**
`备注` 不是装饰，是**审计痕迹**：记录作者原表里出现过的单位歧义、笔误、缺列。
- 用处一：将来某只数看起来离谱时，能立刻知道"是作者原文就错，还是我们算错"。
- 用处二：`口径存疑` 那 5 只（美的/海尔/青岛港/中南传媒/老凤祥）就是靠它隔离出 config 的。
- 所以保留原文，不改成"已换算"叙述——数值列本来就是亿，113/115 行复算全对得上，改备注反而丢掉原始线索。
